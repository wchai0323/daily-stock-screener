# Daily Stock Screener

'성장주 투자 프레임워크 v2'의 **1차 스크리닝을 매일 자동으로 돌리고 결과를 메일로 보내는** 저장소입니다.

```
1차 스크리닝 (자동, 이 저장소) → 종목 선별 (사람) → 체크리스트 검증 (Claude) → 매수 결정 (사람)
```

## 매일 하는 일

미국 장 마감 후(한국시간 화~토 06:30) GitHub Actions가 실행됩니다.

1. **재무 갱신**: SEC EDGAR에서 최근 10-Q·10-K를 낸 기업만 재무를 다시 받습니다. 실적 시즌에는 하루 수백 개, 비시즌에는 수십 개 수준입니다. 45일 넘게 갱신되지 않은 캐시도 조금씩 재수집합니다.
2. **주가 갱신**: Yahoo Finance에서 1년 일봉을 받아 시가총액, 거래대금, 52주 범위, 200일선을 계산합니다.
3. **0단계 유니버스 → 1층 하드 필터(H1~H7, G·C 차선) → 2층 자동 점수(69점)** 를 계산합니다.
4. **전일 결과와 비교**해 신규 진입·이탈 종목과 그 이유를 뽑습니다.
5. 메일을 보내고, 결과를 `data/results/날짜.csv`, 유니버스 전체 지표를 `data/snapshots/날짜.csv.gz`로 커밋합니다.

## 메일 구성

| 섹션 | 내용 |
| --- | --- |
| 보유 종목 점검 | `config/holdings.txt`의 종목 중 오늘 1층을 통과하지 못한 종목과 걸린 조건 |
| 신규 진입 | 오늘 처음 통과한 종목과 진입 근거 (차선, 매출 성장, 가속, 매출총이익률) |
| 이탈 | 어제 통과했다가 오늘 탈락한 종목과 걸린 조건 |
| 자동점수 상위 30 | 섹터·업종, PER(TTM·Forward)·PEG·PSR, 핵심 지표, 진입 참고 태그. ★ = 자동점수 70% 이상 1순위 후보 |
| 첨부 CSV | 통과 종목 전체와 항목별 점수 |

## 자동 점수 범위

2층 100점 중 공개 데이터로 계산 가능한 **69점**만 자동으로 매깁니다.

| 자동 (69점) | 체크리스트 검증 단계에서 채움 (31점) |
| --- | --- |
| S1 성장 8, S2 가속 8, S3 마진 동반 4, S5 매출총이익/자산 8, S6 영업 레버리지 7, S7 Rule of 40 5, S8 희석 7, S9 투자 효율 5, S10 레버리지 3, S12 성장 조정 밸류 5, S13 시가총액 6, S18 공매도 3 | S4 수주잔고 5, S11 역DCF 10, S14 TAM 4, S15 경영진 4, S16 내부자 거래 3, S17 가이던스 3, S18 기관 보유 변화 2 |

H7 중 본사 주소 기준 중국·홍콩·마카오 제외는 자동이고, 지배주주·생산기지·감사의견·재무제표 재작성은 검증 단계에서 확인합니다.

## 처음 설정

### 1. 시크릿 등록

저장소 **Settings → Secrets and variables → Actions → New repository secret**에서 등록합니다.

| 이름 | 값 | 필수 |
| --- | --- | --- |
| `SEC_USER_AGENT` | SEC 요청용 연락처. 예: `Daily Stock Screener 이메일주소` (SEC가 요구하는 형식) | 필수 |
| `SMTP_USER` | 보내는 Gmail 주소 | 메일 발송 시 |
| `SMTP_PASSWORD` | Gmail **앱 비밀번호** (일반 비밀번호 아님. Google 계정 → 보안 → 2단계 인증 → 앱 비밀번호) | 메일 발송 시 |
| `MAIL_TO` | 받는 주소. 여러 명이면 쉼표로 구분 | 메일 발송 시 |
| `SMTP_HOST`, `SMTP_PORT` | Gmail이 아니면 입력 (기본 smtp.gmail.com / 587) | 선택 |

### 2. 첫 실행

**Actions → Daily Stock Screener → Run workflow**

1. 먼저 `max_companies`에 `200`, `skip_mail` 체크로 시험 실행해 오류가 없는지 확인합니다.
2. 이상 없으면 빈 값으로 전체 실행합니다. **첫 전체 실행은 SEC 재무를 처음부터 받느라 30~60분** 걸립니다. 이후에는 캐시를 써서 매일 5~15분 안에 끝납니다.
3. 첫 실행 메일에는 비교 대상이 없어 신규·이탈 섹션이 빠집니다.

### 3. 보유 종목 등록

`config/holdings.txt`에 한 줄에 하나씩 티커를 적어 커밋합니다.

## 알려진 한계

- **실적 반영 시차**: 재무는 SEC 10-Q·10-K 공시 기준입니다. 기업이 실적을 발표한 날이 아니라 10-Q를 낸 날 반영되므로, 며칠에서 길게는 수주 늦을 수 있습니다.
- **해외 공시 기업 제외**: 20-F·40-F로 공시하는 외국 기업(ADR 다수)은 분기 재무가 없어 유니버스에서 빠집니다.
- **업종 분류**: GICS 대신 SEC의 SIC 코드(3자리, 표본 부족 시 2자리)로 업종 기준선(40백분위)을 계산합니다.
- **XBRL 태그 차이**: 기업마다 매출·원가 태그가 달라 일부 기업은 매출총이익률 등이 비어 탈락할 수 있습니다. 이 경우 탈락 사유에 '판정 불가', '없음'으로 표시됩니다.
- 기준값은 연구 기반 출발값이며 백테스트로 검증하지 않았습니다. 바꿀 때는 `screener/config.py`만 고치고 `CHANGELOG.md`에 기록합니다.

```bash
python -m pytest -q
```
